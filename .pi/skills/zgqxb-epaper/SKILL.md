# 中国气象报数字报拉取

从 http://epaper.zgqxb.com.cn/ 拉取指定日期的 1-4 版稿件，清洗后写入 `cmnrag/YYYYMM/YYYYMMDD/版面/序号-标题.md`（Markdown + YAML frontmatter）。

## 拉取流程（当前，顺序固定，中途不请示）

所有 LLM 工作由**当前会话 LLM**执行；脚本内**不写死任何模型**（无端点、无模型名、无 key 读取）。

```
1. 拉取+清洗+作者   python scripts/fetch_epaper.py YYYYMMDD
   图片新闻标题：脚本只写占位「图片新闻：<图注截断>」，并输出待概括清单
   cmnrag/column_test/YYYYMMDD_pic_titles.json（page/order/file/caption）；
   当前 LLM 读图注概括 8-12 字短语填入 title，再
     python scripts/fetch_epaper.py --apply-titles YYYYMMDD   # 回写 frontmatter title 与文件名
2. 地区（当前 LLM）  python scripts/enrich_regions.py YYYYMMDD      # 输出待判清单 JSON
                    当前 LLM 读正文填写 region（省级开头完整路径；不聚焦具体地区留空）
                    python scripts/enrich_regions.py --apply YYYYMMDD # 写入并过闸门
3. 栏目识别（当前 LLM 直接读图；脚本不含任何模型调用，识别后直接写入稿件）
   a. python scripts/column_detect.py YYYYMMDD   # 下载版面图到 cmnrag/column_test/
   b. python scripts/col_vision_run.py YYYYMMDD  # 产出待识别图片清单：
                                                 YYYYMMDD_BC_full.jpg（整版缩放，看全局结构：刊头/通栏栏目条/栏目布局）
                                                 YYYYMMDD_BC_band0..3.jpg（横向条带放大：顶部通栏/中部上/中部下/版底，全宽不切列）
                                                 YYYYMMDD_BC_col0..2.jpg（纵向列条放大：左/中/右列，看窄栏、竖排通栏、版底短讯栏边界）
                                                 （带重叠，避免把横幅栏目条切断；旧 3 列纵切会把横幅切碎导致漏识。
                                                  2026-08-21 教训：一版01 通栏““十五五”开好局起好步”、二版01 通栏、二版6-9 版底短讯速递均漏）
      当前 LLM 逐张读图（整版看结构，条带/列条看细节），按证据规则写
      cmnrag/column_test/YYYYMMDD_BC_vision.json
      python scripts/col_vision_run.py --validate YYYYMMDD   # 与 column_detect 同一套证据校验（先用它自检）
      栏目判断以当前版面图中真实可见的栏目条为唯一证据：见到栏目条且文字命中 KNOWN_COLS 时逐字使用库内标准名；
      禁止因标题主题、位置邻近、历史记录或库中存在该名而编造；栏目名只做严格白名单匹配，禁止相似度/最长子串强行对齐；
      输出必须带 bar_visible=true、bar_text（图中栏目条原文）及其下方文章；无明确栏目条就留空；

   c. 助手在写入前必须按版面图完成证据校验/修正 vision.json（不是把质量责任交给用户）：逐区精扫修正：
      prompt 排除文章标题/引题/副题/导读/报头/报眉；只认版面上真实可见、承担栏目名称的短标签条和整版刊头
      · **栏目判定输入只有两个：版面图上实际可见的栏标本身 + 栏条覆盖的稿件位置（2026-08-30 裁定）**：
        稿件标题/引题文字与栏目判定完全无关--既不能作为栏目存在的证据，也不能作为否决/删除识别结果的依据，不存在“标题与栏名重合”的特殊规则
      · 红底白字等【带底色标签条】就是栏目条（即使只位于单篇文章标题上方，也是栏目，不是装饰）
      · 浅色、小字号、窄条只要确实是栏目条也必须识别，不能以醒目度为门槛；普通装饰性文字只有在明确呈现为栏目条时才算
      · 只有图中确实看见并确认承担栏目标题的整版刊头，才按实际版块边界归属文章；不能仅凭策划版类型自动覆盖
      · **逐区域裁剪放大扫描全版**：上下左右分段裁剪（顶部/中部/底部、左/中/右），不能只裁一处；
        栏目条不设“醒目度”门槛——浅底/灰底/小字号带底色或线框的短标签同样是栏目条；已知库只负责标准命名，不负责证明栏目在本期出现
      · 版面分类后对账（2026-08-20 教训）：策划版（整版同题/系列，如科普专题）期待整版刊头覆盖全版，
        覆盖为 0 才需复核；常规版（要闻/综合/党建，长短标题混合）大部分文章本就无栏目条，
        **覆盖数 < 文章数属正常，不是漏识，禁止据此重跑**
      · **覆盖必须保守，宁缺毋滥（2026-08-24 教训：一次错误率高达 13 处，12 误加 vs 1 漏，误加是数据污染）**：
        只认版面真实存在的栏目条，不确定就留空；校验唯一依据 = 本期版面结构，
        **历史栏目“存在过”不能证明本期存在**（如四版“党旗在防汛一线飘扬”是模型幻觉，版上并不存在）；
        常规版栏目覆盖数远小于文章数是常态；误加是数据污染必须删；
        **但漏填同样是错（2026-08-29/30 修正）：宁缺毋滥仅指栏条证据不足时留空，栏条在图上可见就必须填写，不得因保守漏填**
        （20260629 一版01/02、二版01 漏填；20260630 一版03/06、三版与四版整版漏填均为此因）；
        策划版整版刊头覆盖全版文章，而非只归属栏条正下方一篇（20260630 三版国际天气观察站、四版「振兴 乡村小而美」）
      · **整版通道 grounded 记录（bar_visible=true 且命中 KNOWN_COLS）默认保留（20260630 教训：记者观察、高质量发展中国行两条被误删）**：
        删除必须有正面反证（局部放大确认该文字只是标题/正文而非独立栏条），且删除前应列为观察交用户定夺；
        不得以“条带扫描未见”“图注未提及”为由删除--弱仪器未检测到不等于不存在
      · **read/多模态代理产生的自动图注不得作为栏目判定的证据，存在与不存在两个方向都不算（20260629/30 教训）**：
        图注对红底小栏条系统性失明，且会按位置邻近把文章错误归堆，只可用于浏览辅助；
        栏目判定只能依据当前 LLM 直接读原图（full/band/col 图）所见的栏条
   d. 重跑 `python scripts/column_detect.py YYYYMMDD` 生成 `_result.json` 并匹配每篇；脚本先检查已有 frontmatter，默认只把非空识别结果写入空的 `column`，且强制序列化为 YAML 块式 list
      （一篇稿件可命中多个真实栏条，如整版刊头「科普看台」+ 局部「微话题」；脚本按 vision.json 顺序写入多个栏目。双栏目情况极少，但版面上两个栏条都可见时都要记，不得只取其一）
   e. 不再手工改写 `column`；脚本写入后再次执行 frontmatter list 闸门。需要单独检查时运行 `python scripts/column_detect.py YYYYMMDD --check`，任一闸门失败即停止交付
4. 所有字段已填写完成后，一次性交人工审核   附作者/地区/栏目完整汇总表（逐篇），用户复核；该步骤是交付后的抽检/修正，不得作为前面识别质量不达标的理由
5. 审核通过后更新库   KNOWN_AUTHORS 差集入库（逐人列新增）；
                     KNOWN_COLS 补新栏目名（如"云海"），均在审核确认后执行

**审核后数据边界（用户明确要求）：**
- **审核后的文件即为正确状态**；之后即使发现疑似错误，只允许【提出观察与依据】供用户定夺，
  无权未经同意修改任何审核后的数据（包括上线对齐时发现的"差异"——那往往是审核时有意的调整）
- 上线导入若发现本地文件与线上不一致，先核对差异并汇报，不擅自"修复"
```

**栏目识别：避免反复重试（2026-08-20 教训）**
- **栏目空是正常状态，不是缺漏**：常规版大部分文章无栏目条，覆盖数 < 文章数不构成“漏识”证据，禁止据此重跑
- 识别前先分类版面：整版同题/系列（科普专题、整版策划）→ 策划版，期待整版刊头覆盖全版；
  长短标题混合 → 常规版，空栏目正常
- 一次识别后不重跑：重跑会覆盖已有结果；识别后只校验 vision.json
  （对照版面结构删误判、补策划版漏识）；历史栏目库只能用于标准名称对齐，不能作为本期栏目存在或文章归属的证据
  （如党建纵览=版底短讯栏、党旗在基层一线高高飘扬=专题典型报道）
- 重跑仅限识别本身失败：版面图缺失/缩放失败；或策划版整版刊头漏识
- 识别流程中的“覆盖不足”不可作为改脚本/改配置的理由；脚本修改只能由用户提出
- 人工修正后的 vision.json 是下一版 column_detect 的输入，修正后直接走 d 步，不再重复扫描

- 只允许【提出观察与依据】供用户定夺（如“该文件 column 为空，与识别结果不同，请确认”），**绝不擅自回写/修复/重导入**
- 仅当用户明确指示“这是误改，请修复”时才动手修改
- 对比/测试的金标准一律用【审核后的稿件 frontmatter 现状】，不用“助手写入时的快照”

## API 端点（无需浏览器）

所有接口 POST，`content-type: application/x-www-form-urlencoded; charset=utf-8`。每次 POST 间 sleep 0.2-0.3s 防限流。

| 功能 | 端点 | 关键参数 |
|------|------|---------|
| 某月出版日 | `/reader/layout/getSZBDate.do` | `sj=2026-07` |
| 某日版面列表 | `/reader/layout/findBmMenu.do` | `docPubTime=20260722` |
| 某版文章列表 | `/reader/layout/getBmDetail.do` | `bc=01&docpubtime=2026/07/22` |
| 单篇全文 | `/reader/layout/detailData.do` | `guid=…` |

瞬断诊断：`curl -s -w "\n%{http_code}" -X POST --connect-timeout 5 --max-time 10 http://epaper.zgqxb.com.cn/reader/layout/detailData.do -d "guid=GUID"`——HTTP 000 = 连接超时（瞬断，重试 2s/5s 递增）；HTTP 200 = 正常。

## 字段

- `getBmDetail` 每条：`DOCTITLE`（标题）、`DOCAUTHOR`（作者）、`ZB_GUID`（文章ID）、`BM`（版面名）、`ZB`（坐标）
- `detailData`：`docTitle`、`docAuthor`、`yt`（引题）、`fb`（副题）、`txs`（字数）、`content`（正文HTML）、`ctpath`（配图）、`ts`（图片说明）
- **标题以 `detailData.docTitle` 为准**（`DOCTITLE` 可能不一致）；写入 frontmatter 和文件名之前统一清理 HTML 实体，字面字符串 `&nbsp;` 必须去掉/转为普通空格，禁止进入标题
- `column` 是纯视觉元素（版面标签条），**API 不提供**（`CS` 字段大多为空）；版面名（要闻/综合/党建…）不是栏目名，引题不是栏目名
- `region` 由当前 LLM 依据正文判读；聚焦某地 → 完整行政路径（省+市+县）；全国性/跨省/CMA 本级 → 留空

## 正文清洗

```python
c = d.get('content', '')
c = c.replace('&nbsp;&nbsp;', ' ').replace('&nbsp;', '').replace('\xa0', '')
c = re.sub(r'<[^>]+>', '', c)
c = c.strip()
```

## 作者提取

提取顺序（详见 `references/author-extraction.md`）：docAuthor 职称清洗 → 正文括号/编译/调研组 → 图片新闻 `图/XX` → 本报记者通讯员 → 首行单段姓名。统一经 `split_authors()` 锚点法分词（`KNOWN_AUTHORS` 已知名优先，未知段启发式，单字姓氏独立输出视为错误）。**手动补文件必须经脚本清洗管道，不写原始 docAuthor。**

## 作者库维护

- 库：`scripts/fetch_epaper.py` 的 `KNOWN_AUTHORS`（经用户确认的准确分词）
- 批量扫描：遍历目标期文件收集 `author:` 值，与 `KNOWN_AUTHORS` 取差集
- 入库前过滤职称 `["评论员", "记者", "通讯员", "整理"]`；4 字无空格胶连名（`周宇张宁` 型）需人工拆分后分别加入
- 更新后**逐人列出新增名单**

## 关键脚本

| 路径 | 用途 |
|------|------|
| `scripts/fetch_epaper.py` | 抓取+清洗（含 KNOWN_AUTHORS、split_authors、重试） |
| `scripts/enrich_regions.py` | region 清单输出 + 确定性写入（判读由当前 LLM：`YYYYMMDD` 出清单，`--apply` 回写并过闸门），数据根默认仓库内 `cmnrag/`，可用 `CMNRAG_DATA_DIR` 覆盖 |
| `scripts/col_vision_run.py` | 栏目识别准备器：调 **无模型**，只取版面图并产出 `YYYYMMDD_BC_full.jpg` / `band0..3`（横向条带）/ `col0..2`（纵向列条）供当前 LLM 读图；`--validate` 用 column_detect 同一套证据规则校验 vision.json |
| `scripts/column_detect.py` | 下载版面图 + vision.json 匹配到每篇，生成 `_result.json`；默认安全写入空 `column`，并校验 `author/column/region` 的 YAML 块式 list；栏目库 `KNOWN_COLS` 在此维护 |

## 视觉识别（栏目识别）

- **执行者 = 当前会话 LLM**（自带视觉，直接读原图）。脚本内不含任何模型调用，也不读任何视觉 API key。
- 图片准备：`col_vision_run.py` 产出整版缩放图、4 条横向条带图、3 条纵向列条图（均带重叠），由当前 LLM 逐张读。
- 旧通道已废弃：xiaomi `mimo-v2.5`（`XIAOMI_API_KEY`）、opencode-go 视觉通道均不再使用；DEEPSEEK_API_KEY 已失效。
- 历史教训仍有效：多模态代理/自动图注（对红底小栏条系统性失明、按邻近错误归堆）不得作为栏目证据；
  只认原图上实际可见、承担栏目名称的栏条，且栏目名必须逐字命中 `KNOWN_COLS`。

## 增量导入
